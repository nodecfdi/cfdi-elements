`@nodecfdi/cfdi-elements` está compilado con `tsdown` en formato ESM sin empaquetar (`unbundle: true`) con declaraciones `.d.ts` completas para cada subruta.

## Importaciones por subruta (*tree-shaking*)

Cada módulo de elementos tiene su propio punto de entrada en `package.json`:

```ts
import { Comprobante } from '@nodecfdi/cfdi-elements/cfdi40';
import { Nomina } from '@nodecfdi/cfdi-elements/nomina12';
import { Pagos } from '@nodecfdi/cfdi-elements/pago20';
```

Al importar únicamente las subrutas que utilizas, los empaquetadores (Vite, Rollup, esbuild, Webpack) evitan incluir el código de los demás complementos (como `detallista` o `cartaporte31`) en tu bundle final.

## Tipos de atributos por elemento

Cada elemento exporta tanto su clase como el tipo unión de sus atributos válidos con el sufijo `Attributes`:

```ts [tipos-atributos.ts]
import type { AttributesRecord } from '@nodecfdi/cfdi-core/types';
import type { ComprobanteAttributes, ConceptoAttributes } from '@nodecfdi/cfdi-elements/cfdi40';
import { Comprobante } from '@nodecfdi/cfdi-elements/cfdi40';

const datosComprobante: AttributesRecord<ComprobanteAttributes> = {
  Serie: 'A',
  Folio: '10',
  Fecha: '2026-01-25T12:00:00',
  TipoDeComprobante: 'I',
  Exportacion: '01',
  LugarExpedicion: '64000',
};

const conceptoBase: AttributesRecord<ConceptoAttributes> = {
  ClaveProdServ: '84111506',
  Cantidad: '1',
  ClaveUnidad: 'E48',
  Descripcion: 'Servicio',
  ValorUnitario: '100.00',
  Importe: '100.00',
  ObjetoImp: '02',
};

const comprobante = new Comprobante(datosComprobante);
comprobante.addConcepto(conceptoBase);
```

## Tipos compartidos (`@nodecfdi/cfdi-elements/types`)

Para tipar estructuras de `AbstractElement` o los resultados de `SumasConceptos`, importa desde `@nodecfdi/cfdi-elements/types`:

```ts
import type {
  ElementInterface,
  SumaExentos,
  SumaLocal,
  SumaRetenciones,
  SumaTraslados,
} from '@nodecfdi/cfdi-elements/types';
```
