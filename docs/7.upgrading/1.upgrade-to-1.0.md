---
title: Actualizar de 0.5.x a 1.0.0
description: Guía de migración y cambios incompatibles (breaking changes) para actualizar @nodecfdi/cfdi-elements desde la versión 0.5.x a 1.0.0.
navigation:
  icon: i-tabler-arrow-up-circle
---

La versión `1.0.0` consolida el ecosistema completo de elementos del SAT, adopta `@nodecfdi/cfdi-core` v2 y migra toda la aritmética a `Decimal` y ESM puro. Revisa cada cambio antes de actualizar.

## Pasos para actualizar

::steps

### 1. Actualiza Node.js y el formato de módulos

El requisito mínimo de Node.js sube de `>=18 <=22 || ^16` a **`^22.13.0 || ^24 || ^26`**.

Además, se elimina la compilación CommonJS (`dist/commonjs/*`): el paquete ahora se distribuye **únicamente en ESM** (`dist/*.js`) y **IIFE** (`dist/iife/*.iife.js`). Si tu proyecto aún usa CommonJS, migra a `"type": "module"` en tu `package.json` o utiliza Node.js 22.13+ con soporte para `require(esm)`.

### 2. Actualiza la dependencia `@nodecfdi/cfdi-core`

`@nodecfdi/cfdi-core` pasa de `peerDependencies` (`>=0.6.1`) a `dependencies` con la versión **`^2.0.0`**. Actualiza tu proyecto si importas utilidades directamente desde `@nodecfdi/cfdi-core`:

```bash
pnpm add @nodecfdi/cfdi-elements@^1.0.0 @nodecfdi/cfdi-core@^2.0.0
```

### 3. Migra los valores numéricos de `SumasConceptos` a `Decimal`

En `0.5.x`, `SumasConceptos` y los tipos `SumaTraslados`, `SumaExentos`, `SumaRetenciones` y `SumaLocal` devolvían `number`. En `1.0.0` todos los importes, bases y tasas devuelven instancias de `Decimal` (reexportado por `@nodecfdi/cfdi-core`).

::code-group

```ts [Antes (0.5.x)]
const sumas = new SumasConceptos(comprobante, 2);
const total: number = sumas.getTotal();
const subTotal: number = sumas.getSubTotal();
const impuestos = sumas.getTraslados();
// impuestos[key].Importe era number
```

```ts [Después (1.0.0)]
import { formatNumber } from '@nodecfdi/cfdi-core';

const sumas = new SumasConceptos(comprobante, 2);
const total = sumas.getTotal().toNumber();
const totalStr = formatNumber(sumas.getTotal(), 2);
const impuestos = sumas.getTraslados();
// impuestos[key].Importe y .Base son Decimal
```

::

### 4. Actualiza clases que extiendan `AbstractElement`

Se eliminó la dependencia `ts-mixer` y el método interno `__init`. Si tenías elementos propios extendiendo `AbstractElement`:

- Usa **exportación con nombre** (`import { AbstractElement } from '@nodecfdi/cfdi-elements'`) en lugar de exportación por defecto en rutas internas.
- Si sobreescribías `__init`, mueve esa lógica al `constructor` llamando a `super(attributes, children)`.
- Opcionalmente pasa el tipo unión de atributos al genérico `AbstractElement<MiAtributos>`.

::code-group

```ts [Antes (0.5.x)]
import AbstractElement from '@nodecfdi/cfdi-elements';
```

```ts [Después (1.0.0)]
import { AbstractElement } from '@nodecfdi/cfdi-elements';
```

::

### 5. Verifica atributos tipados y namespaces SAT

- Todos los elementos ahora tienen tipado estricto mediante `AttributesRecord<TAttributes>` en constructores y métodos `add*` / `multi*`. TypeScript reportará error si pasas un atributo que no pertenece al esquema del nodo.
- Las URLs de namespaces (`xmlns:*`) y `xsi:schemaLocation` del SAT se normalizaron de `https://` a `http://` conforme a los XSD oficiales del SAT. Si tus pruebas comparan cadenas XML literales contra snapshots antiguos, actualiza los snapshots.

::

## Resumen rápido de compatibilidad

| Aspecto | Versión `0.5.x` | Versión `1.0.0` |
| :--- | :--- | :--- |
| **Node.js** | `>=18 <=22 \|\| ^16` | `^22.13.0 \|\| ^24 \|\| ^26` |
| **Formatos** | ESM + CommonJS (`tshy`) | ESM + IIFE (`tsdown`) |
| **`@nodecfdi/cfdi-core`** | Peer `>=0.6.1` | Dependencia `^2.0.0` |
| **Aritmética en `SumasConceptos`** | `number` | `Decimal` |
| **Dependencia `ts-mixer`** | Incluida | Eliminada |
| **Tipado de atributos** | `Record<string, unknown>` | `AttributesRecord<TAttributes>` |
