Todos los elementos de `@nodecfdi/cfdi-elements/cfdi40` siguen una API fluida y consistente para construir el árbol XML de un CFDI 4.0 sin preocuparte por el orden de los nodos ni por los namespaces.

## Convención de métodos

Cada elemento padre expone tres tipos de métodos según la cardinalidad del nodo hijo en el XSD del SAT:

- **`get<Hijo>()`**: obtiene el hijo único si ya existe, o lo crea y lo adjunta automáticamente (`helperGetOrAdd`).
- **`add<Hijo>(attributes?, children?)`**:
  - Si el hijo es único (como `Emisor`, `Receptor`, `InformacionGlobal` o `Impuestos`), actualiza sus atributos sobre la instancia existente y la devuelve.
  - Si el hijo es repetible (como `Concepto`, `CfdiRelacionados`, `Traslado` o `Retencion`), crea una nueva instancia, la agrega y la devuelve.
- **`multi<Hijo>(...attributesList)`**: agrega múltiples hijos repetibles en una sola llamada y retorna `this` para encadenar métodos.

## Ejemplo completo de CFDI 4.0

```ts [cfdi40.ts]
import { nodeToXmlString } from '@nodecfdi/cfdi-core';
import { SumasConceptos, SumasConceptosWriter } from '@nodecfdi/cfdi-elements';
import { Comprobante } from '@nodecfdi/cfdi-elements/cfdi40';

const comprobante = new Comprobante({
  Serie: 'F',
  Folio: '1234',
  Fecha: '2026-01-15T10:30:00',
  FormaPago: '03',
  Moneda: 'MXN',
  TipoDeComprobante: 'I',
  Exportacion: '01',
  MetodoPago: 'PUE',
  LugarExpedicion: '64000',
});

// CFDI relacionados (opcional, repetible)
comprobante
  .addCfdiRelacionados({ TipoRelacion: '04' })
  .multiCfdiRelacionado(
    { UUID: '11111111-2222-3333-4444-555555555555' },
  );

// Emisor y Receptor (únicos)
comprobante.addEmisor({
  Rfc: 'EKU9003173C9',
  Nombre: 'ESCUELA KEMPER URGATE',
  RegimenFiscal: '601',
});

comprobante.addReceptor({
  Rfc: 'URE180429TM6',
  Nombre: 'UNIVERSIDAD ROBOTICA ESPAÑOLA',
  DomicilioFiscalReceptor: '65000',
  RegimenFiscalReceptor: '601',
  UsoCFDI: 'G03',
});

// Conceptos con impuestos trasladados y retenidos
const concepto = comprobante.addConcepto({
  ClaveProdServ: '84111506',
  Cantidad: '1',
  ClaveUnidad: 'E48',
  Unidad: 'Servicio',
  Descripcion: 'Servicios de consultoría',
  ValorUnitario: '1000.00',
  Importe: '1000.00',
  ObjetoImp: '02',
});

concepto.addTraslado({
  Base: '1000.00',
  Impuesto: '002',
  TipoFactor: 'Tasa',
  TasaOCuota: '0.160000',
  Importe: '160.00',
});

concepto.addRetencion({
  Base: '1000.00',
  Impuesto: '001',
  TipoFactor: 'Tasa',
  TasaOCuota: '0.100000',
  Importe: '100.00',
});

// Calcular y escribir SubTotal, Total e Impuestos globales automáticamente
const sumas = new SumasConceptos(comprobante, 2);
new SumasConceptosWriter(comprobante, sumas, 2).put();

const xml = nodeToXmlString(comprobante, true);
console.log(xml);
```

## Orden automático de hijos

`Comprobante` define `getChildrenOrder()` con la secuencia oficial del SAT:

1. `cfdi:InformacionGlobal`
2. `cfdi:CfdiRelacionados`
3. `cfdi:Emisor`
4. `cfdi:Receptor`
5. `cfdi:Conceptos`
6. `cfdi:Impuestos`
7. `cfdi:Complemento`
8. `cfdi:Addenda`

Aunque agregues `cfdi:Conceptos` antes que `cfdi:Emisor`, al serializar a XML el orden siempre será válido según el esquema XSD.

::tip
Para conocer en detalle cómo `SumasConceptos` y `SumasConceptosWriter` calculan los totales e impuestos, consulta [Sumas de Conceptos](/packages/cfdi-elements/utilities/sumas-conceptos).
::
